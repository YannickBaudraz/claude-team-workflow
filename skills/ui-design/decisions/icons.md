# Iconography and identity marks

Read this before deciding icon style, source, labels, text pairing and state, and marks for people, groups and objects.

Floors: `CRAFT.md`. Targets: `density.md`. Shape meanings: `form.md`. Colours: `colour.md`.

## Inputs

- The typeface's stroke, terminals and corners at body size (`type.md`); radii; density; character; themes.
- Concepts and objects that may need icons, and their states.
- How often and how expertly users meet each icon; ages, cultures, languages, devices.
- Entity kinds the product shows (people, groups, objects, any others); uploaded images or picked symbols.
- An existing set's coverage, variants, licence, format, size and future changes.

## Criteria and evidence

- **Style:** systems derive it from typeface, shape language, density and brand, matching or contrasting on purpose; asserted, untested. They split on caps and corners without usability evidence: character decisions. Near consensus on construction, not look: detail the smallest size can hold, one drawing logic and weight per size across the set, a shared grid. How simple, flat or dimensional the drawing is stays a character decision. A concept may override a rule to read better.
- **Style and speed:** weak, mixed evidence; outline and solid differ little, less once learned.
- **Recognition:** small, older studies agree: the picture's closeness to the function matters first, familiarity later; icon-only costs novices early, when labels help most; one search study found words faster.
- **Labels:** sources disagree. Label nearly everything, navigation always; or let near-universal common actions, which are few, stand alone; or where less weight is needed. Each lone icon gets a stated reason.
- **Pairing with text:** systems fix icon size and weight per text style, weight in step with the text's unless the style contrasts on purpose. Convention, untested.
- **State:** systems give fill, slash and enclosure different meanings and disagree on fill as emphasis. Untested.
- **Themes:** strokes can look heavier light on dark (one system, one unreviewed study); sources disagree whether meaningful icons meet the non-text or text floor in `CRAFT.md`.
- **Identity:** several systems code entity kind by shape, and split on new kinds; convention, untested, one way among others to keep kinds distinct. Fallback styles: weak evidence, opinion only. One system draws user-chosen symbols from a separate vocabulary, read as content, not function.

## Options space

- **Style:** drawing (stroke, fill, mixed, illustrative), weight per size, caps, corners, default variant (outline, solid or other), colour (one, two-tone, several), perspective, detail, how literal; each matched, contrasted or independent; exceptions.
- **Source:** existing set, custom, or a base extended under its rules; a gate before adding one (needed, exists, confusable); an owner.
- **Use:** which concepts earn an icon's weight; labels always, by element kind, or by familiarity; one meaning per icon, or some set by context.
- **Size ladder:** icon size, weight and alignment per text style; strokes across sizes (separate masters, optical sizing, stepped strokes); small icons informing, paired with text or in a larger target.
- **State:** variant per state (default, selected, on, off, unavailable); predefined pairs; icon or container showing interaction.
- **Identity:** per kind: image, generated mark, initials, glyph tile, thumbnail; shape, reserved or not; fallback chain; user-symbol vocabulary; sizes; presence and status placement.

## Testing

- Squint at the set: one family?
- Recognition out of context, label hidden; interpretation in context; first click; memorability later; across the audience's ages, cultures, languages. Practitioner methods, no thresholds; weigh effort between frequent and rare icons.
- Each pairing at its smallest size, every theme: the weight relation chosen (matched or contrasted) reads as intended, floors per `CRAFT.md`.
- Every toggled icon has its pair; states distinct at the smallest size.
- A list of fallback marks: entities still distinct.

## Write down

Each choice with its reason and evidence strength. Style rules, each one's match or contrast, exceptions. Source, gate, owner. Per icon: meaning, a "use to" line, label rule. Size table, alignment. State pairs. Per entity kind: mark, shape, fallback, sizes. Tests run; untested claims.
